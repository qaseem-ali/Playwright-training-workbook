PART 1: HTML and Locator Foundations

1. What is an HTML element?

A web page is built from HTML elements. Examples include input fields, buttons, links, labels, tables, rows, divs, spans, and images.

HTML Example
<button>Submit</button> <input type="text" name="username"> <a href="/claims">Claims</a>
Playwright Explanation

In automation, Playwright interacts with these elements. A locator is the instruction that tells Playwright which element you want to target in the DOM.

2. Tag, attribute, and attribute value

Understanding the structure of an HTML tag is mandatory before writing selectors.

<input type="text" name="username" id="user-field" class="form-control">
Tag: input — Tells you what kind of HTML element it is.
Attributes: type, name, id, class — Extra information attached to the element.
Attribute Values: text, username, user-field, form-control — The actual values.
Key Takeaway: When inspecting HTML, start by identifying the tag, then look for attributes that are stable and unique.

3. What does a locator do?

A locator defines how Playwright finds elements on the page.

const username = page.locator('input[name="username"]'); await username.fill("admin");

The first line does not fill anything or search the DOM immediately. It creates a locator representing elements matching the selector. The second line triggers auto-waiting and performs the action.

Mental Model: Selector → Element Resolution → Action / Assertion

4. Locator vs element

A locator is not a static reference to an already-fetched DOM node. Playwright locators re-evaluate dynamically whenever an action or assertion is performed.

const submit = page.getByRole("button", { name: "Submit" }); await submit.click();

This strict separation enables Playwright to handle dynamic UI re-renders, auto-waiting, and retries seamlessly.

5. Uniqueness & strictness

A strong locator normally identifies the intended element uniquely. If your selector matches multiple elements, Playwright will throw a strictness violation when executing single-element actions like click() or fill().

const buttons = page.locator("button"); console.log(await buttons.count());
Count Debugging Rule: Count is a valuable debugging technique. 0 means the selector found nothing; 1 is normally ideal; >1 means you should narrow the locator or explicitly work with a collection.

PART 2: Playwright's Predefined Locators

Before learning CSS and XPath, learn Playwright's built-in semantic locators. These produce resilient, readable tests because they describe the interface in a way that mimics how human users interact with the UI.

6. getByRole()

Top Recommendation

Role-based locating asks: What kind of interactive or semantic element is this? Examples include button, link, heading, textbox, checkbox, radio, combobox, listbox, option, row, cell.

await page.getByRole("button", { name: "Submit" }).click(); await page.getByRole("textbox", { name: "Username" }).fill("admin");

What is the Accessible Name?

The accessible name is the name assistive technologies use to identify an element. It can come from visible text, an associated <label>, aria-label, or aria-labelledby.

<button aria-label="Close dialog">X</button>
await page.getByRole("button", { name: "Close dialog" }).click();
Good Practice: Prefer getByRole() when the role and accessible name clearly represent the user's action.

7. getByText()

Use getByText() when visible text is the primary identifying feature.

await page.getByText("Transaction Created").click();

If the same phrase occurs in multiple places, scope the locator using a container:

await page.locator(".notification-panel").getByText("Transaction Created").click();

8. getByLabel()

Connects a form control with its explicitly associated <label> element.

<label for="username">Username</label> <input id="username">
await page.getByLabel("Username").fill("admin");

9. getByPlaceholder()

Targets input fields using their placeholder text attribute.

<input placeholder="Enter username">
await page.getByPlaceholder("Enter username").fill("admin");
Caution: Useful when placeholder is stable. Do not use if placeholders are generated or localized dynamically.

10. getByAltText()

Targets elements (commonly images) using their alternative text attribute.

<img alt="Company logo" src="/logo.png">
await page.getByAltText("Company logo").click();

11. getByTitle()

Targets elements using their HTML title attribute.

<button title="Close">X</button>
await page.getByTitle("Close").click();

12. getByTestId()

Targets elements using dedicated testing attributes (by default data-testid).

<button data-testid="submit-transaction">Submit</button>
await page.getByTestId("submit-transaction").click();
Engineering Rule: A test ID is an explicit contract between engineering and automation. Avoid random test IDs added solely to bypass good locator strategy.

13. Decision Guide for Predefined Locators

If you know... Start with... Reason
User's action / element role getByRole() Expresses semantic intent and accessibility role
Visible text on screen getByText() Simple, readable, and user-facing
Form field label getByLabel() Maps directly to field purpose
Stable placeholder text getByPlaceholder() Useful for unlabeled form inputs
Image alternative text getByAltText() Accessibility-oriented image selection
Stable title attribute getByTitle() Uses HTML title metadata
Explicit test contract getByTestId() Resilient against UI changes
DOM structure / attributes locator() Maximum control over CSS/XPath selectors

PART 3: CSS Selectors from Zero

CSS selectors select elements for styling, but Playwright uses them to identify DOM targets. Understanding CSS syntax allows you to build custom page.locator() expressions effortlessly.

14 & 15. Tag Selector

Selects elements by their HTML tag name directly.

page.locator("input"); page.locator("button"); page.locator("select");
Common Mistake: A tag by itself is usually too broad because pages typically contain multiple inputs or buttons.

16. ID Selector (#)

In CSS, # denotes an element ID.

<input id="username">
page.locator("#username");
Warning — Dynamic IDs: Beware of generated IDs like user-837462 that change on every page load or build.

17. Class Selector (.)

In CSS, . denotes a class name.

<button class="submit-button">Submit</button>
page.locator(".submit-button");

Single vs Chained vs Space-Separated Classes:

.btn.primary (No Space) → Same element must have both btn and primary classes.
.btn .primary (With Space) → Selects an element with class primary that is a descendant inside an element with class btn.

18–21. Attribute Selectors

Square brackets [...] select elements based on attributes and attribute values.

18. Exact Attribute Match
page.locator('[name="username"]'); page.locator('[type="email"]');
19. Attribute Presence (Exists)
page.locator("[data-testid]"); // Matches any element where data-testid exists
20. Combined Tag + Attribute
page.locator('input[name="username"]'); // Input tag with name="username" page.locator('button[type="submit"]');
21. Multiple Attributes
page.locator('input[type="text"][name="username"]'); // Must satisfy both attribute rules

PART 4: CSS Relationships & Operators

22 & 23. Descendant vs Direct Child

<div class="login-form"> <div class="form-group"> <input name="username"> </div> </div>
Syntax Type Meaning
.login-form input Descendant (Space) Finds input anywhere inside .login-form, regardless of nesting depth.
.login-form > input Direct Child (>) Finds input only if it is an immediate child of .login-form.

24. Sibling Concepts

CSS supports sibling relationships to find adjacent or following elements.

<label>Username</label> <input name="username">
page.locator("label + input"); // Adjacent sibling: input immediately after label

25–28. Attribute Value Substring Operators

Operator Meaning Example Selector Matches Attribute Value
^= Starts with [id^="submit-"] submit-12345
$= Ends with [id$="-submit"] btn-submit
*= Contains substring [id*="submit"] main-submit-btn
~= Matches space-separated word [class~="active"] card active selected

PART 5: Advanced Playwright Locator Techniques

29. :has-text()

Narrows a selector down by selecting an element that contains specific visible text inside itself or its descendants.

<button class="action">Submit</button>
page.locator('button:has-text("Submit")').click(); page.locator('.form-actions button:has-text("Submit")').click();

30 & 31. :has() & Power of Hierarchy

:has() selects an element that contains another inner element matching a specific selector.

<div class="user-card"> <span>David</span> <button>Edit</button> </div>
page.locator('.user-card:has-text("David")').getByRole("button", { name: "Edit" }).click();
Container Philosophy: Identify the stable business container first (e.g., David's user card), then perform the action inside that container.

32. Locator Chaining

Chain locators together to break complex DOM queries into clear steps.

const row = page.locator('.transaction-row:has-text("Premium Adjustment")'); await row.getByRole("button", { name: "Edit" }).click();

33. filter()

Filters an existing collection of locators based on text or child element conditions.

const rows = page.locator(".transaction-row"); await rows.filter({ hasText: "Premium Adjustment" }) .getByRole("button", { name: "Edit" }) .click();

34. Positional Selection: first(), last(), nth()

page.locator("button").first(); page.locator("button").last(); page.locator("button").nth(2); // 0-indexed (selects the 3rd button)
Engineering Warning: Use positional selection only when position is part of the business requirement. If you use nth() because you couldn't construct a proper locator, refactor to business container scoping.

PART 6: XPath from Beginner to Advanced

XPath navigates XML/HTML nodes. While Playwright semantic locators and CSS are preferred, XPath is valuable for complex DOM axes and reverse parent/sibling traversals.

35. Relative Root (//)

page.locator('//input[@name="username"]');

// searches anywhere in the document.

36. Attribute (@)

//input[@id="username"] //button[@type="submit"]

@ denotes attribute names.

37. Text Matching

//button[text()="Submit"] //button[contains(text(), "Submit")]

text() matches exact text; contains() handles partial text.

38–40. Parent & Ancestor

//input[@id="username"]/.. //input[@id="username"]/ancestor::form[1]

/.. moves to parent; ancestor:: finds matching higher containers.

41–42. Following & Preceding Axes

//span[text()="David"]/following::button[1] //button[@id="edit"]/preceding::span[1]

Finds elements appearing after or before the reference node in document order.

XPath Strategy Rule: Do not use dynamic DevTools-generated XPaths. Write short, intentional XPaths only when CSS/Playwright methods cannot express the relationship.

PART 7: CSS vs XPath vs Playwright Locators

Situation Recommended Starting Point Reason
Button with clear role / name getByRole() Semantic, resilient, user-facing
Field with accessible label getByLabel() Expresses field business intent directly
Stable automation contract getByTestId() Explicit, isolated test hook
Unique stable element ID locator("#id") Simple, highly performant CSS
Stable element attribute locator('[name="..."]') Precise attribute match
Business container + action filter() / :has() / chaining Strong hierarchical scoping
Repeated elements with intentional order nth() Position is an explicit requirement
Complex DOM axis relationship XPath Required for reverse DOM traversal

PART 8: Locator Engineering & Stability

Good vs Bad Locator Comparison

❌ Brittle Anti-Pattern
page.locator("button").nth(7); page.locator("div:nth-child(4) > div:nth-child(2) > button");

Why it fails: Relies on exact DOM structure and index position. Inserting an element or changing layout breaks the test immediately.

✅ Robust Engineering
page.locator(".transaction-row") .filter({ hasText: "Premium Adjustment" }) .getByRole("button", { name: "Edit" });

Why it succeeds: Identifies the business record first, then finds the action within that container. Unaffected by unrelated UI movements.

47. Dynamic IDs

Evaluate whether an ID is persistent. If id="submit-12345" changes per run, use prefix matching: [id^="submit-"].

48. Generated Classes

Avoid build-generated utility classes like css-1a2b3c. Rely on structural domain classes like transaction-row.

PART 9: Real-World Locator Patterns

51. Login Form

<form class="login-form"> <label for="username">Username</label> <input id="username" name="username"> <label for="password">Password</label> <input id="password" name="password"> <button type="submit">Login</button> </form>
await page.getByLabel("Username").fill("admin"); await page.getByLabel("Password").fill("secret"); await page.getByRole("button", { name: "Login" }).click();

52 & 53. Repeated Transaction Rows & Tables

<tr> <td>CLM-1001</td> <td>Open</td> <td><button>Edit</button></td> </tr>
await page.locator("tr") .filter({ hasText: "CLM-1001" }) .getByRole("button", { name: "Edit" }) .click();

54. Modals and Overlays

<div class="modal"> <h2>Delete Transaction</h2> <button>Cancel</button> <button>Delete</button> </div>
await page.locator(".modal").getByRole("button", { name: "Delete" }).click();

PART 10 & 11: Debugging & Common Mistakes

Locator Failure Diagnostics Table

Symptom Likely Cause Action / Fix
count() === 0 Incorrect selector, delayed render, or iframe scope issue Verify HTML inspection, check iframes, or assert visibility
count() > 1 Selector is too broad Scope to container or add filter() condition
Strictness Violation Action expected 1 element but found multiple Narrow locator using business context or accessibility role
Works locally, fails in CI Environment-specific IDs, dynamic data differences Replace unstable attributes with persistent test IDs or roles

⚠️ Top 4 Anti-Patterns to Eliminate

1. Overusing nth() as a Rescue Do not use nth(7) just because it happened to pass during test writing.
2. Unscoped getByText() getByText("Edit") will break when multiple Edit links exist on the page.
3. Massive DevTools XPaths Never commit selectors like //html/body/div[2]/div[1]/div[3]/button.
4. Blind Faith in Self-Healing Self-healing should not mask underlying locator defects or wrong click targets.

PART 12: Locator Design Rules for a Team

Rule 1: Prefer semantic Playwright locators when they express user action clearly.
Rule 2: Use stable test IDs when an intentional test-ID contract exists.
Rule 3: Prefer stable domain attributes over styling-only CSS classes.
Rule 4: Always scope repeated controls to their business container.
Rule 5: Avoid fixed indexes (nth) unless position is the requirement.
Rule 6: Avoid deep DOM structural paths.
Rule 7: Reserve XPath for relationships genuinely benefiting from XPath axes.
Rule 8: Validate uniqueness using count() during development.
Rule 9: Locators must survive unrelated layout and styling changes.
Rule 10: Readability is key: another engineer should instantly understand the target.

🏢 Workbook F: Realistic Enterprise QA Scenarios

Scenario 1 — Claims List (50+ Rows)

A claims page displays 50 claims. Each row has Claim Number, Status, and actions like View, Edit, Add Transaction. Click Add Transaction for CLM-1024.

page.locator(".claim-row") .filter({ hasText: "CLM-1024" }) .getByRole("button", { name: "Add Transaction" });

Why: Safer than selecting the 24th index row because row order changes based on sorting or filters.

Scenario 4 — Code Review Challenge

A developer submits a pull request containing this locator:

//html/body/div[4]/div[2]/div[1]/div[3]/button[1]

Senior QA Feedback: Reject. Tightly coupled to absolute DOM structure. Any minor markup update breaks the test suite. Replace with role, label, or container-scoped filter.

page.locator("input")

🧠 Final Mental Model: The 7 Diagnostic Questions

1 WHAT ELEMENT IS IT? (button, input, row, link, table cell)
2 WHAT MAKES IT UNIQUE? (role, text, label, ID, test-id, attribute)
3 IS THAT PROPERTY STABLE? (persistent vs build-generated / localized)
4 IS THERE A BUSINESS CONTAINER? (row, card, modal, panel)
5 CAN I SCOPE THE TARGET? (chaining, filter, :has)
6 IS THE LOCATOR UNIQUE? (count() === 1)
7 WILL IT SURVIVE UNRELATED UI CHANGES? (resilient architecture)

"A selector that passes the test is not automatically a good selector."

Locator engineering quality is part of test framework quality.
